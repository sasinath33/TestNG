📖 Chapter 9: Listeners

9.1 What are Listeners?

Listeners in TestNG are interfaces that let you “listen” to test events.

They can:

Track test start, success, failure, or skip events

Generate custom logs or reports

Retry failed tests automatically

Modify test behavior at runtime

9.2 Commonly Used Listeners

Listener Purpose

ITestListener Captures events like test start, success, failure, skip

IRetryAnalyzer Retries failed tests automatically

IAnnotationTransformer Dynamically modifies annotations at runtime

9.3 Using ITestListener

This listener tracks test execution events.

Example

java

import org.testng.ITestListener;

import org.testng.ITestResult;

public class MyListener implements ITestListener {

@Override

public void onTestStart(ITestResult result) {

System.out.println("Test Started: " + result.getName());

}

@Override

public void onTestSuccess(ITestResult result) {

System.out.println("Test Passed: " + result.getName());

}

@Override

public void onTestFailure(ITestResult result) {

System.out.println("Test Failed: " + result.getName());

}

@Override

public void onTestSkipped(ITestResult result) {

System.out.println("Test Skipped: " + result.getName());

}

}

Applying Listener

xml

<listeners>

<listener class-name="com.example.MyListener"/>

</listeners>

9.4 Using IRetryAnalyzer

This listener retries failed tests automatically.

Example

java

import org.testng.IRetryAnalyzer;

import org.testng.ITestResult;

public class RetryAnalyzer implements IRetryAnalyzer {

int count = 0;

int maxRetry = 2;

@Override

public boolean retry(ITestResult result) {

if(count < maxRetry) {

count++;

return true;

}

return false;

}

}

Applying to a Test

java

import org.testng.annotations.Test;

public class RetryDemo {

@Test(retryAnalyzer = com.example.RetryAnalyzer.class)

public void testRetry() {

System.out.println("Executing test...");

assert false; // Force failure

}

}

9.5 Using IAnnotationTransformer

This listener modifies annotations dynamically at runtime.

Example

java

import org.testng.IAnnotationTransformer;

import org.testng.annotations.ITestAnnotation;

import java.lang.reflect.Constructor;

import java.lang.reflect.Method;

public class AnnotationTransformer implements IAnnotationTransformer {

@Override

public void transform(ITestAnnotation annotation, Class testClass,

Constructor testConstructor, Method testMethod) {

annotation.setRetryAnalyzer(RetryAnalyzer.class);

}

}

Applying Listener

xml

<listeners>

<listener class-name="com.example.AnnotationTransformer"/>

</listeners>

9.6 Notes

ITestListener → Best for logging and reporting.

IRetryAnalyzer → Best for retrying flaky tests.

IAnnotationTransformer → Best for dynamic test behavior.

Listeners are powerful for building robust frameworks with custom reporting and error handling.

9.7 Exercises

Basic Listener: Implement ITestListener to log test start and end events.

Retry Practice: Create a test that fails intentionally and use IRetryAnalyzer to retry it twice.

Challenge: Use IAnnotationTransformer to apply retry logic dynamically to all tests without modifying each test method.

7. Retry Failed Tests Example

package listenerDemo;

import org.testng.IRetryAnalyzer;

import org.testng.ITestResult;

public class RetryAnalyzer implements IRetryAnalyzer {

int retryCount = 0;

int maxRetry = 2;

@Override

public boolean retry(ITestResult result) {

return true;

}

return false;

}

}

TestNG Listeners – How to Run Each Listener

This document explains how to run each TestNG listener with simple steps.

1. ITestListener

- Used to listen to test pass, fail, skip.

- Attach using @Listeners annotation or testng.xml.

- Run test class as TestNG test.

2. ISuiteListener

- Listens to suite start and finish.

- Must be added in testng.xml.

- Run testng.xml as TestNG Suite.

3. IInvokedMethodListener

- Runs before and after every method.

- Added in testng.xml.

- Run testng.xml.

4. IExecutionListener

- Runs before and after complete TestNG execution.

- Added in testng.xml.

- Run testng.xml.

5. IReporter

- Used for custom report generation.

- Added in testng.xml.

- Runs after all tests finish.

6. IMethodInterceptor

- Used to control test execution order.

- Added in testng.xml.

- Run testng.xml.

7. IAnnotationTransformer

- Modifies TestNG annotations at runtime.

- Must be added in testng.xml.

- Run testng.xml.

Important Rule:

- Class level → @Listeners

- Suite level → testng.xml
